# PaperOps 工程约定

本文约束 PaperOps 新代码。`src/react_agent` 是迁移期间保留的 v0.1 原型，不作为新代码范例；需要复用的能力应按本约定迁入 `src/paperops`，而不是直接复制旧实现。

## 1. 类型边界

- LangGraph 内部 State 使用 `TypedDict`，只保存恢复工作流所需的小型状态、标识符和 artifact 路径。
- API、外部客户端和 LLM 决策的输入输出使用 Pydantic 模型，在系统边界完成校验。
- MinerU 解析正文、图片和其他大型内容写入 artifact 目录，State 不保存完整文档。
- 外部服务通过 `Protocol` 定义能力，节点依赖接口，不直接依赖具体 HTTP SDK。

## 2. 结构化输出

- 影响路由、重试、人工审批或外部写入的 LLM 决策必须使用 Pydantic 结构化输出。
- 结构化结果校验失败时只能重试、失败关闭或进入人工审核，不使用正则表达式猜测控制决策。
- 确定性条件优先使用普通代码，例如文件存在性、重试次数、正文长度和引用完整性。
- 面向用户的最终回答和摘要可以使用自由文本，不为形式统一而强制包装成 Pydantic 模型。

## 3. Prompt 与消息角色

- `SystemMessage` 只包含稳定的角色、目标、约束和输出规则。
- 用户查询使用 `HumanMessage`；工具结果使用 `ToolMessage`；论文正文等外部内容作为明确标记的数据传入。
- 不把用户查询、论文内容或工具返回值拼接到 System Prompt，避免不可信内容获得系统指令优先级。
- Prompt 模板集中放在 `src/paperops/prompts.py`，节点负责组装状态与调用，不内嵌大段提示词。

## 4. 工作流副作用

- 解析、上传和删除等副作用必须具备幂等键；重放 checkpoint 不得重复创建外部资源。
- 节点先取得结果，再一次性返回状态更新，不在执行过程中原地修改 State。
- State 记录结构化失败原因、尝试次数和外部资源 ID，保证中断后能够判断从哪里恢复。
- 不可逆操作和超出自动重试上限的情况进入明确的人工确认节点。

## 5. 测试要求

- 节点逻辑优先使用 Fake Client 做确定性单元测试，不依赖真实 API Key。
- 至少覆盖正常完成、自动重试、重试耗尽、人工中断与恢复、checkpoint 恢复和重复执行幂等性。
- 真实 MinerU、RAGFlow 或模型调用只放在显式标记的集成测试中。
