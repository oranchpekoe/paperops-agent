# PaperOps MVP 产品说明

## 1. 问题定义

实验室成员将科研 PDF 解析并上传知识库时，通常只能确认接口调用成功，无法确认标题、正文、公式和表格是否被可靠保留，也无法确认知识库能否召回支持答案的原文片段。

PaperOps 在 MinerU 和 RAGFlow 之间增加质量闭环：解析结果先经过规则检查；不确定样本再交给 LLM 语义审核；低置信度任务暂停等待人工确认；完成上传后通过文档级测试问题验收检索效果。

## 2. 第一版用户故事

> 作为一名需要整理无人机强化学习论文的实验室学生，我希望提交一篇 PDF 后，系统能够解析、检查、必要时重试或请求确认，并在上传 RAGFlow 后告诉我该文档是否真正可检索，以减少逐篇人工检查。

## 3. 输入与输出

### 输入

- 一篇本地 PDF；
- 目标 RAGFlow 知识库；
- 可选的人工审核意见。

### 输出

- 原文件哈希和任务 ID；
- MinerU 解析产物路径；
- 规则与语义质量决策；
- 重试、异常和人工审批记录；
- RAGFlow 文档 ID；
- 检索测试问题和证据片段；
- 结构化验收报告。

## 4. PR2 单文档状态机

```text
PENDING
  -> PARSING
  -> QUALITY_CHECK
       -> RETRY -> PARSING
       -> WAITING_APPROVAL -> UPLOADING
       -> UPLOADING
  -> RETRIEVAL_EVAL
  -> COMPLETED | FAILED
```

PR2 使用 Fake Client，不依赖真实 MinerU、RAGFlow 或模型 API。

## 5. 验收条件

- 正常文档能完成完整状态流转；
- 低质量解析最多自动重试两次；
- 无法可靠判断时进入人工审核状态；
- 外部服务异常被记录为结构化错误；
- 大段 Markdown 不写入 LangGraph State；
- 同一个文件哈希不会重复创建不可区分的任务；
- 每条条件分支均有自动化测试。

## 6. 暂不包含

- 批量并发调度；
- 多租户和 RBAC；
- 真实 MinerU/RAGFlow HTTP 集成；
- Redis、Kubernetes和独立任务队列；
- Agentic RL 训练；
- 通用聊天、长期偏好记忆和四模式自动路由。

## 7. 后续评测方向

使用公开的纯文本、双栏、公式密集、表格/图片密集论文，对比：

1. MinerU 解析后直接上传；
2. PaperOps 质量闭环后上传。

核心指标为最终解析成功率、自动恢复率、人工介入率、检索命中率、答案依据准确率、平均处理时间和故障恢复率。
